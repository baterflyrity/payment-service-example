## Что сделано
- `src/payment_service/config.py` — добавлен флаг `enable_docs: bool = False` (env `ENABLE_DOCS`). По умолчанию интерактивная документация отключена: `/docs`, `/redoc`, `/openapi.json` не раскрывают схему API без `X-API-Key`; включаются только для локальной разработки.
- `src/payment_service/entrypoints/api/app.py` — `docs_url`/`redoc_url`/`openapi_url` включаются только при `ENABLE_DOCS=true`; обоснование выбора в docstring; подключён роутер health.
- `src/payment_service/entrypoints/api/health.py` (новый) — `GET /health` (liveness, без ключа и без БД) и `GET /health/ready` (readiness: `SELECT 1`, при ошибке 503 в едином формате). Проверка БД берётся из зависимости `get_database_check`, переопределяемой в тестах.
- `src/payment_service/infrastructure/db/session.py` — добавлена `ping_database()`: `sqlalchemy` остаётся только в infrastructure (F2), entrypoints вызывает её.
- `src/payment_service/entrypoints/api/errors.py` — единый JSON ошибок `{"error": {"code", "message"}}` для доменных ошибок, `HTTPException` (включая 401) и ошибок валидации запроса. Коды: `unauthorized`, `not_found`, `idempotency_conflict`, `validation_error`, `domain_error`, `not_ready`, `http_error`; заголовки исключения (в т.ч. `WWW-Authenticate`) сохраняются.
- `docker-compose.yml` — healthcheck сервиса `api` переведён с `/openapi.json` на `/health`.
- `tests/test_payments_api.py` — обновлены проверки под новый формат ошибок; добавлены 401 без ключа и с неверным ключом для `POST`/`GET`, тело 404/409/422, `/health` 200, `/health/ready` 200/503 через overrides, отключённые `/docs` и `/openapi.json` (404).

## Критерии готовности
- [x] 401 без ключа/с неверным ключом на каждом эндпоинте (`POST` и `GET` платежей).
- [x] 404 — тело `{"error": {"code": "not_found", ...}}`.
- [x] 409 — тело `{"error": {"code": "idempotency_conflict", ...}}`.
- [x] 422 — тело `{"error": {"code": "validation_error", ...}}` (невалидный payload и отсутствующий `Idempotency-Key`).
- [x] `GET /health` — 200 без ключа; `/health/ready` — 200 при доступной БД и 503 при недоступной.
- [x] Документация закрыта: `/docs` и `/openapi.json` отключены по умолчанию (флаг `ENABLE_DOCS`), выбор задокументирован в docstring `create_app`.

## Проблемы и вне scope
- `ENABLE_DOCS`, `/health`, `/health/ready` и формат ошибок пока не описаны в README/`.env.example` — T09; записано в `NOTES.md`.
- У `consumer` в compose остаются неиспользуемые `API_KEY`, `OUTBOX_*` и `depends_on: api: healthy` (pre-existing) — T09.
- `/health/ready` проверяется тестами через подмену зависимости (без живой БД); проверка на реальном Postgres остаётся на T08/T09.
- В `errors.py` использован `HTTP_422_UNPROCESSABLE_CONTENT`, чтобы не добавлять новых предупреждений об устаревшем `HTTP_422_UNPROCESSABLE_ENTITY`; само предупреждение из недр Starlette остаётся.
