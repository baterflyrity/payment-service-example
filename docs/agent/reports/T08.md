## Статус
Выполнено

## Что сделано
- Структура тестов приведена к трём уровням:
  - `tests/unit` — чистые unit-тесты (domain, application, consumer delivery, Pydantic-схемы, архитектура);
  - `tests/integration` — тесты с реальным PostgreSQL (API, репозитории/UoW, гонка одинаковых ключей, retry/DLQ на RabbitMQ);
  - `tests/e2e` — smoke против поднятого `docker compose`.
- `tests/conftest.py` — оставлен только независимый от окружения фикстур `api_key` (без подключения к БД и без проверки `TEST_DATABASE_URL` на import). Фикстуры `test_engine`/`db_connection`/`client` перенесены в `tests/integration/conftest.py`, поэтому `pytest tests/unit` больше не требует базы.
- Перемещены без изменения логики:
  - `tests/test_idempotency.py` → `tests/unit/application/test_idempotency.py`;
  - `tests/test_payment_schemas.py` → `tests/unit/test_payment_schemas.py`;
  - `tests/test_payments_api.py` → `tests/integration/test_payments_api.py` (использует реальную БД через фикстуру `client`).
- `pyproject.toml` — объявлены маркеры `integration`, `rabbit`, `e2e`. Маркер `integration` проставлен в интеграционных модулях (`pytestmark`), в `test_consumer_dlq.py` — вместе с `rabbit`.
- `tests/unit/test_architecture.py` (новый) — AST-проверка инвариантов SPEC §3 без импорта проверяемых модулей:
  - `domain/` не импортирует `sqlalchemy`, `fastapi`, `pydantic`, `faststream`, `httpx`;
  - `domain/` не зависит от `application`/`infrastructure`/`entrypoints`;
  - `application/`, `entrypoints/api/` и legacy-шим `api/` не импортируют `sqlalchemy`;
  - `application/` не зависит от `infrastructure`/`entrypoints`;
  - `.gitignore` не содержит `alembic`. Тесты параметризованы по файлам, поэтому нарушение указывает конкретный модуль.
- `tests/integration/test_create_payment.py` — добавлен тест атомарности: `CreatePaymentService` с UoW, падающим на `commit` после `payments.add` + `outbox.add`, не оставляет ни платежа, ни outbox-события (проверка отдельной сессией).
- `tests/e2e/test_flow.py` (новый, маркер `e2e`) — POST платежа → polling `GET /api/v1/payments/{id}` до `succeeded|failed` → получение webhook. Приёмник webhook поднимается отдельным контейнером (`docker run -d --network <сеть compose> python -c ...`) из образа сервиса `consumer`, тело запроса складывается в смонтированный tmp-каталог. Без `docker`/запущенного compose тест корректно пропускается (`skip`), а не падает.
- Устаревших тестов, дублирующих новые, не найдено: старые `test_outbox_publisher.py`/`test_consumer_retries.py`/`test_payment_processor.py` были удалены ещё в T05/T06; оставшиеся модули покрывают разные уровни (hash/схемы/domain/application/integration).

## Проблемы и вне scope
- E2E-тест требует, чтобы стек был уже поднят и `API_KEY` совпадал с `E2E_API_KEY`/`API_KEY`; при отсутствии docker или сервиса `consumer` тест пропускается. Запуск описан в docstring модуля; в README (T09) стоит добавить раздел про e2e.
- `ruff format --check` показывает расхождения в ряде существующих файлов (форматирование в проекте не применялось и не входит в DoD); `ruff check` зелёный.
- Тест `rabbit` по умолчанию пропускается без `RABBITMQ_URL` (pre-existing); в compose брокер доступен на `127.0.0.1:25672` под пользователем `payments` — записано в NOTES.
- Pre-existing: `docker compose ps/logs/stop` падают без переменной `API_KEY` из-за `${API_KEY:?...}`; неиспользуемые env и `depends_on: api: healthy` у `consumer` — T09. Записано в NOTES.
