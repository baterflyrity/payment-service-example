# T01. Миграции Alembic в репозитории и рабочая Docker-сборка (F1)

## Статус
Выполнено

## Что сделано
- `.gitignore` — удалена запись `/alembic/`, каталог миграций теперь попадает в репозиторий. `.dockerignore` не исключает `alembic/` (изменений не потребовалось).
- `alembic/env.py` — async-окружение Alembic: URL берётся из `payment_service.config.settings.database_url`, `target_metadata = payment_service.models.Base.metadata`; поддержан offline-режим.
- `alembic/script.py.mako` — стандартный шаблон новых ревизий (совместим с Python 3.14, `str | None`).
- `alembic/versions/0001_initial.py` — вручную написанная начальная миграция: таблицы `payments` (все колонки, CHECK `amount > 0`, `currency`, `status`, уникальный `idempotency_key`, индекс `ix_payments_status_created_at`) и `outbox` (все колонки, индекс `ix_outbox_published_created_at`); `downgrade` удаляет таблицы и индексы.
- `docker-compose.yml` — добавлен одноразовый сервис `migrations` (`alembic upgrade head`, `restart: "no"`), запускаемый после healthy `postgres`; из команды `api` убран `alembic upgrade head`; `api` и `consumer` зависят от `migrations` через `condition: service_completed_successfully`.
- `.env.example` сверен с compose: все используемые переменные (`DATABASE_URL`, `RABBITMQ_URL`, `API_KEY`, `POSTGRES_*`, `RABBITMQ_DEFAULT_*`, `OUTBOX_*`) присутствуют; `docker compose config` проходит.

## Права доступа
- Исходно: репозиторий принадлежал `root:root`, `sudo -u user git status` падал с «dubious ownership».
- Исправлено: `chown -R user:root .` (gid пользователя `user` = 0), каталоги `2775` (setgid), файлы `664`, `.git` — `g+rwX` и setgid на каталогах, `git config --local core.sharedRepository=group`.
- `sudo -u user git -C ... status` — работает; `git status` от root — работает.
- `sudo -u user touch` в корне проекта и в `.git/objects` — успешно (тестовые файлы удалены).
- `docker run --rm -v ...:/w alpine ls -la` — содержимое видно; после работы владелец/права приведены к единому виду (`user:root`, каталоги 2775, файлы 664).

## Проблемы и вне scope
- Первая строка `.env.example` содержит `[TEMPLATE]` — выглядит как случайный маркер. Compose и pydantic-settings её tolerate (проверено), поэтому не менял; вынесено в `NOTES.md` для T09.
- `consumer` зависит от healthcheck `api` — это существующее поведение, в границы T01 не входит.
