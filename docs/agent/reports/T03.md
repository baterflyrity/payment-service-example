## Что сделано
- `src/payment_service/infrastructure/db/orm.py` — `Base`, `PaymentORM`, `OutboxORM` перенесены из `models/` без изменения схемы; классы переименованы (`Payment` → `PaymentORM`, `Outbox` → `OutboxORM`), таблицы/колонки/ограничения/индексы сохранены (`metadata` → атрибут `metadata_json`).
- `src/payment_service/infrastructure/db/session.py` — `engine`, `SessionFactory`, `get_session` (перенесены из `db.py`).
- `src/payment_service/infrastructure/db/mappers.py` — `payment_to_orm`, `apply_payment_to_orm`, `payment_to_domain`, `outbox_to_message`; ORM ↔ domain без бизнес-логики.
- `src/payment_service/infrastructure/db/repositories.py`:
  - `SqlAlchemyPaymentRepository`: `add` (вставка нового или обновление существующего по `id`), `get`, `get_by_idempotency_key`, `get_for_update` (`FOR UPDATE`); `IntegrityError` по уникальности `idempotency_key` преобразуется в доменный `DuplicateIdempotencyKey` (распознаются имена `uq_payments_idempotency_key` и autogenerated `payments_idempotency_key_key`).
  - `SqlAlchemyOutboxRepository`: `add` (payload содержит `event_id`, `payment_id`, `occurred_at`), `lock_unpublished` (`WHERE published_at IS NULL ORDER BY created_at, id LIMIT n FOR UPDATE SKIP LOCKED`), `mark_published` (batch), `mark_failed` (`attempts + 1`, `last_error`).
- `src/payment_service/infrastructure/db/uow.py` — `SqlAlchemyUnitOfWork`: сессия и репозитории на один UoW; `commit` фиксирует, `__aexit__` делает rollback при исключении или отсутствии commit, затем закрывает сессию; `rollback` сбрасывает флаг commit.
- `src/payment_service/domain/events.py`, `domain/ports.py` — тип `OutboxMessage.id` и аргументов `mark_published`/`mark_failed` приведён к `UUID`: PK `outbox` в миграции 0001 — UUID, тип `int` из T02 был несовместим. Схема БД не менялась.
- `alembic/env.py` — `target_metadata` теперь из `payment_service.infrastructure.db.orm`.
- Удалены `src/payment_service/models/` и `src/payment_service/db.py`; импорты в `api/main.py`, `api/payments.py`, `workers/consumer.py`, `workers/outbox_publisher.py`, `services/payment_processor.py` и старых тестах переведены на новые пути (ORM-классы импортированы как `PaymentORM as Payment` / `OutboxORM as Outbox` — это временно, до T04/T06/T08).
- `tests/integration/test_repositories.py` — 7 интеграционных тестов на БД `payments_test`: add/get/get_by_idempotency_key/get_for_update, обновление существующего платежа, дубликат ключа → `DuplicateIdempotencyKey`, rollback UoW без commit, rollback при исключении, `SKIP LOCKED` (два параллельных UoW), `mark_published` + `mark_failed`.

## Для следующей задачи
- Новые пути: `payment_service.infrastructure.db.{orm,session,repositories,uow,mappers}`; `payment_service.db` и `payment_service.models` удалены.
- UoW: `async with SqlAlchemyUnitOfWork(SessionFactory) as uow: ...; await uow.commit()`; репозитории — `uow.payments`, `uow.outbox`. Без `commit` изменения откатываются.
- `payments.add` делает `flush` и сам различает insert/update по `id`. После `DuplicateIdempotencyKey` сессия UoW непригодна — обрабатывать ошибку снаружи и перечитывать ключ в новом UoW.
- `Payment.pull_events()` отдаёт `PaymentCreated`; их нужно передать в `uow.outbox.add(...)` в том же UoW, что и `payments.add(...)`.
- `lock_unpublished` возвращает `OutboxMessage` с `id: UUID`; публиковать payload, затем `mark_published([msg.id])` в том же UoW.
- `mark_failed` увеличивает `attempts` и пишет `last_error`; `mark_published` выставляет `published_at`.
- Для интеграционных тестов поднимается `postgres` из compose и БД `payments_test` (создана в этом окружении).
