- тот же ключ с другим body (`amount=999.00`) → `409` `{"error":{"code":"idempotency_conflict",...}}`;
- POST без `X-API-Key` → `401` `{"error":{"code":"unauthorized","message":"Invalid or missing API key"}}`;

## Проблемы и вне scope
- `ruff format --check` по-прежнему расходится с существующим кодом (pre-existing, форматирование не входит в DoD; проект проверяет `ruff check`).
- Интеграционные тесты используют `Base.metadata.create_all/drop_all`, а не Alembic; миграции проверены отдельно (`downgrade base`/`upgrade head` на `payments_test`).
- `docker compose ps/logs/down` без `.env`/`API_KEY` падают из-за `${API_KEY:?...}` — осознанное поведение (README требует `cp .env.example .env`).
- Ручной curl с `webhook_url=https://merchant.example/...` приводит к ожидаемому retry→DLQ из-за неразрешимого хоста; для проверки успешного webhook используется e2e-тест.
- Замечания, зафиксированные в `docs/agent/NOTES.md` (раздел T10): заголовок из одних пробелов нормализуется HTTP-парсером в пустое значение, поэтому сообщение ошибки — `Field required`, а не `must not be empty`; при необходимости можно добавить собственный валидатор с более точным текстом.
- При остановленной инфраструктуре `docker compose ps` показывает остановленные контейнеры основного проекта — на сдачу не влияет, `docker compose down -v` в чистом клоне выполнен.
